# ATLAS CHECKPOINT — Task 019: Forex wiring (crypto → forex pivot, step 2)

## Objective
This task wires forex into Atlas's existing PAPER pipeline as an opt-in market (grant
GRANT-TASK-019-FOREX-WIRING, registry v5.103; owner message "Devam et", 2026-10-25). Setting `ATLAS_MARKET=FOREX`
makes Atlas trade forex data from a MetaTrader 5 demo terminal. CRYPTO stays the default until the crypto removal
(Task 020).

Authority is unchanged: live DENIED, production NONE.

## Completed
- **`core/atlas_config.py`.** `ATLAS_MARKET` accepts CRYPTO (the default) or FOREX. Any other value, and
  FOREX together with `ATLAS_FILL_MODEL=BOOK`, is refused at startup.
- **`core/application.py`.** A `market` parameter. In FOREX the application:
  - uses the `mt5` exchange and `config/instrument_rules_mt5.json`;
  - quotes in USD in the risk policy, and uses the forex universe when no symbols are given;
  - turns Fear & Greed off (crypto sentiment);
  - refuses the BOOK fill model and funding sentiment (both Binance-only);
  - wires the session guard into MarketLoop.
- **`core/market_loop.py`.** `market_session_open` (default None, so crypto is unchanged). While the market is
  closed, neither BUY nor SELL is routed (`MARKET_CLOSED`, metric `market_closed_skipped`). A guard that raises or
  answers anything but True counts as closed.
- **`exchange/market_feed.py`.** Accepts the `mt5` exchange. Forex bars carry the absent exchange volume fields as
  None (never zero), and the candle processor keeps them absent. Binance candles still require their volume fields.
- **`main.py`.** Passes the market through, and reads the trade universe from the market's rules file.
- **`atlas_finance/forex/instruments.py`.** `instrument_rule_fields()`: step and minimum are the volume in lots
  times the contract size; the tick is the point; min_notional is 0.01 (MT5 has none); venue maxima are withheld.
- **`tools/refresh_mt5_instrument_rules.py`.** Writes the MT5 rules from a demo terminal: validate, write a temp
  file, fsync, reload, `os.replace`, print a diff. No git, and a failure leaves the file untouched.

## Architecture decisions
- **Opt-in, not default.** MT5 runs only on Windows and is unverified on the owner's terminal. The default flips
  in Task 020.
- **Missing sentiment lowers confidence.** Without the crypto sentiment source, fusion counts it as missing against
  a claim over the expected roster (NB-4/NB-5), so forex confidence is lower, never higher.
- **Costs unchanged.** 0.1 % per side plus 5 bps is far above typical major-pair spreads, i.e. conservative. A forex
  cost model is an owner decision.

## Known issues / Risks (registry known_issues_v5_103)
- **HIGH bucket below the minimum lot.** At 10,000 USD paper capital with no leverage, the HIGH bucket (about 1,000
  USD) is below 0.01 lot, so those entries are refused (fail closed).
- **Long-only.** No short forex view is taken.
- **Weekend gaps.** Positions are held through the weekend, so Monday's gap is taken in full.
- **Shared helpers.** The MT5 rules tool reuses private helpers of the Binance rules tool; they move to a shared
  module in Task 020.
- **Never run against a real MT5 terminal.** The unknowns in v5.102 still apply.
