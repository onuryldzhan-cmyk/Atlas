# REM-001 Gate 1: read-only study and plan (2026-09-28)

Read-only. Nothing here changes a registry, a gate or an authority.
Source: `governance/current/ATLAS_MILESTONE_REGISTRY_v5.16.json`.

## FACT

- Gate 1 had 9 deliverables (registry line ~747).
  - D1, D2, D3 (import graph), D4, D5 and D6 were produced and are PENDING_OWNER_REVIEW.
  - D7, D8 and D9 were never produced. Their original specification is permanently lost (GOV-DRIFT-005).
- A later record set `gate_1_state` = **CERTIFICATION_PATH_CLOSED**, previous value OPEN_NOT_CERTIFIED (line ~11318–11321).
  - Its words: "Gate 1, as originally defined, will never be CERTIFIED".
  - It named the evidence base that replaces Gate 1: the tested safety packages listed in the same record.
- The registry's top-level field is still `feature_expansion_status = PAUSED_PENDING_REM_GATE_1` (line 8).
  - v5.x records carry it forward "unchanged" (e.g. line ~11590).

## CONFLICT

- **Expected:** the feature freeze has an exit condition that can be met.
- **Actual:** the freeze waits for Gate 1, and Gate 1's certification path is closed for good.
- **Evidence:** registry line 8 compared with line ~11319.
- **Impact:** the freeze can never lift under its own rule. Every new feature stays blocked, or needs a one-off owner grant, which is how Phase 2–3 work has run so far.
- **Decision Required (owner):** what replaces "Gate 1" as the condition for lifting the freeze.

## INFERENCE

The freeze was meant to hold until the architecture was mapped and understood. That purpose is largely served by D1–D6 together with the maintained generators:
- `tools/build_architecture_inventory.py` (closure and map, 110 modules);
- `tools.build_rem001_gate1_maps construction`.

Both are regenerated and checked in CI. What is left is a decision, not engineering work.

## RECOMMENDATION (plan, owner picks one)

A. **Re-key the freeze to Phase 2–3 closure (recommended).**
   - A successor registry sets `feature_expansion_status = PAUSED_PENDING_PHASE_2_3_CLOSURE`.
   - It states that Gate 1 is replaced as the exit condition, and why.
   - Once the owner approves the Phase 2–3 completion record, expansion is limited to the next roadmap phase only, never a new phase. Rule 10 stays in force.

B. **Keep the freeze, with explicit owner grants per package.** This is today's practice, written down so it is no longer an implicit contradiction.

C. **Define a new Gate 1 successor checklist.**
   - D1–D6 accepted by the owner.
   - The closure/map checks are green in CI.
   - D7–D9 are recorded as not applicable.
   - The owner signs it.
   - This takes more paperwork and gives no more safety than A.

None of these changes an authority: live DENIED, production NONE, autonomous deployment DENIED.
